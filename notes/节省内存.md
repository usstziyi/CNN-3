在 `load_state_dict(assign=True)` 之后，模型参数虽然已经是“真实权重”了，但它们此时**仍然在 CPU 上**（因为权重文件是从磁盘读到 CPU 内存的）。

`.to(device)` 就是整个流程的**最后一步物理搬运**。

### 🔄 完整三步走的内存状态变化

| 步骤 | 代码 | 参数在哪 | 内存占用 | 比喻 |
| :--- | :--- | :--- | :--- | :--- |
| ① 建骨架 | `with torch.device("meta"): model = resnet18()` | Meta（虚无） | ≈ 0 | 画图纸 |
| ② 填权重 | `model.load_state_dict(sd, assign=True)` | **CPU** | ~45MB | 把砖块放到工地地面 |
| ③ 搬设备 | `model.to("cuda")` | **GPU** | GPU ~45MB, CPU 释放 | 把砖块砌到楼上 |

### 🔍 `.to(device)` 在这一步具体做了什么？

```python
model = model.to("cuda")
```

1.  **分配 GPU 显存**：为每个参数在 GPU 上申请对应大小的显存
2.  **拷贝数据**：将 CPU 上的权重数值复制到 GPU 显存中
3.  **释放 CPU 内存**：CPU 上的旧张量引用计数归零，被垃圾回收
4.  **递归处理**：对模型中所有子模块、buffer（如 BN 的 running_mean）执行同样操作
5.  **返回自身**：支持链式调用

### ⚠️ 为什么不能跳过这一步？

`assign=True` 只是解决了 **"加载时不产生双倍内存"** 的问题，但它**不负责设备转移**。如果你不做 `.to(device)`：

```python
# 权重在 CPU，输入在 GPU → 报错！
input_tensor = torch.randn(1,3,224,224).to("cuda")
output = model(input_tensor)  
# ❌ RuntimeError: Expected all tensors to be on the same device, 
#    but found at least two devices, cuda:0 and cpu!
```

PyTorch **不会自动对齐设备**，模型和输入必须手动放在同一设备上。

### 💡 一个容易混淆的点

有人可能会问：*能不能在 meta device 上直接 `.to("cuda")`，省去 CPU 中转？*

```python
with torch.device("meta"):
    model = resnet18()
model = model.to("cuda")       # ✅ 不报错，但参数仍是 meta 张量！
model.load_state_dict(sd, assign=True)  # ❌ 权重会被加载到 CPU，而非 GPU
```

这是**不行**的。因为：
-   `.to("cuda")` 作用在 meta 张量上时，只改变元数据中的 device 标记，不分配显存（没有数据可搬）
-   后续 `load_state_dict(assign=True)` 仍然从磁盘读到 CPU，不会感知到你之前设过的 device 标记

所以**正确顺序必须是**：先 `assign=True` 填入真实权重（CPU），再 `.to(device)` 搬到目标设备。这个顺序不可颠倒。

### 📌 一句话总结

> `assign=True` 解决了 **“怎么省内存地拿到权重”**，`.to(device)` 解决了 **“怎么把权重放到正确的计算设备上”**。两者各司其职，缺一不可。
