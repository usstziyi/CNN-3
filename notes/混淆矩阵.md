这两行代码用于计算**归一化混淆矩阵（Normalized Confusion Matrix）**，它将原始的预测计数转换为**按真实类别归一化的比例**，从而消除类别样本数量不平衡对可视化分析的影响。

以下是逐行深度解析：

### 1. 计算原始混淆矩阵
```python
cm = confusion_matrix(labels.numpy(), preds.numpy())
```
-   **输入转换**：`.numpy()` 将 PyTorch Tensor 转为 NumPy 数组（sklearn 不接受 Tensor）。同样需注意 GPU Tensor 需先 `.cpu()`。
-   **返回值 `cm`**：一个形状为 `(num_classes, num_classes)` 的整数矩阵。
    -   **行（axis=0）**：真实标签（Ground Truth）
    -   **列（axis=1）**：模型预测标签
    -   **`cm[i][j]`**：真实类别为 `i` 但被预测为 `j` 的样本**绝对数量**
-   ⚠️ 注意 sklearn 的行列约定与部分教材相反，务必确认文档版本。

### 2. 按行归一化（核心操作）
```python
cm_normalized = cm.astype("float") / cm.sum(axis=1, keepdims=True)
```

| 操作 | 作用 | 为什么必要 |
| :--- | :--- | :--- |
| `cm.astype("float")` | 将整数矩阵转为浮点型 | 避免 Python 3 整除截断，确保除法结果为小数而非 0 |
| `cm.sum(axis=1)` | 沿列方向求和 → 得到**每个真实类别的总样本数** | 作为归一化的分母 |
| `keepdims=True` | 保持求和结果的维度为 `(n, 1)` 而非 `(n,)` | **关键！** 使 NumPy 广播机制能正确地将每一行除以对应的行和；若省略，`(n,)` 会按列广播，导致完全错误的归一化结果 |

> 📌 **归一化后的语义**：`cm_normalized[i][j]` 表示"在所有真实类别为 `i` 的样本中，被预测为 `j` 的**比例**"。因此**每一行的元素之和恒等于 1.0**。

### 💡 为什么要归一化？以 CIFAR-10 为例

假设测试集中 "cat" 有 1000 张，"bird" 只有 100 张：

| 指标 | 原始 cm | 归一化 cm_normalized |
| :--- | :--- | :--- |
| cat→dog 误判数 | 150 | 150/1000 = **15%** |
| bird→dog 误判数 | 30 | 30/100 = **30%** |

-   看原始矩阵：cat→dog (150) 远大于 bird→dog (30)，似乎 cat 的问题更严重。
-   看归一化矩阵：bird 的误判率 (30%) 实际上是 cat (15%) 的两倍，**bird 才是更需要关注的短板**。

> ⚠️ **三种归一化方式的区别**
> -   **按行归一化**（本代码）：回答"真实为 i 的样本被预测成了什么？"→ 最常用，直接对应 Recall
> -   **按列归一化** (`axis=0`)：回答"预测为 j 的样本中有多少是真的？"→ 对应 Precision
> -   **全局归一化** (`cm.sum()`)：所有元素之和为 1 → 仅用于展示整体分布占比，实践中较少使用
>
> 选择哪种取决于你的分析目标。**诊断模型弱点用按行归一化，评估预测可信度用按列归一化。**
