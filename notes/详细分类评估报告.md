以下是逐部分解析：

### 1. 数据准备与转换
```python
labels_resnet.numpy(), preds_resnet.numpy()
```
-   **`labels_resnet` / `preds_resnet`**: 通常是 PyTorch Tensor 类型的真实标签和模型预测标签。
-   **`.numpy()`**: `classification_report` 是 scikit-learn 函数，不接受 Tensor 输入，必须先转换为 NumPy 数组。
-   ⚠️ **前提条件**: 这两个 Tensor 必须在 CPU 上。如果它们在 GPU 上，需先调用 `.cpu().numpy()`，否则会报错。

### 2. 核心参数解释

| 参数 | 值 | 作用 |
| :--- | :--- | :--- |
| `y_true` | `labels_resnet.numpy()` |  ground truth 真实标签 |
| `y_pred` | `preds_resnet.numpy()` | 模型预测标签 |
| `target_names` | `CIFAR10_CLASSES` | 将数字标签 (0-9) 映射为可读类别名（如 "airplane", "car" 等），使报告人类可读 |
| `digits` | `4` | 所有指标保留 **4 位小数**，默认是 2 位；对于 CIFAR-10 这种类别间差异较小的基准测试，更高精度有助于区分细微性能差别 |

### 3. 输出报告包含的关键指标

生成的报告会为 CIFAR-10 的每个类别输出一行，包含以下四列：

-   **Precision（精确率）**: $\frac{TP}{TP + FP}$ — 模型预测为该类的样本中，真正属于该类的比例。**高 Precision = 低误报**。
-   **Recall（召回率）**: $\frac{TP}{TP + FN}$ — 该类所有真实样本中，被模型正确识别的比例。**高 Recall = 低漏检**。
-   **F1-Score**: $2 \times \frac{Precision \times Recall}{Precision + Recall}$ — Precision 和 Recall 的调和平均数，综合衡量单类性能。
-   **Support**: 该类别在测试集中的真实样本数量（CIFAR-10 每类均为 1000）。

报告底部还会汇总三行全局指标：

| 汇总行 | 含义 | 适用场景 |
| :--- | :--- | :--- |
| **accuracy** | 整体准确率 | 类别均衡时（CIFAR-10 满足）可直接使用 |
| **macro avg** | 各类指标的**算术平均**（不考虑 support） | 关注**少数类**表现，对类别不平衡敏感 |
| **weighted avg** | 按 support **加权平均** | 反映整体期望性能，与 accuracy 通常接近 |

### 💡 为什么不能只看 Accuracy？

以 CIFAR-10 为例，假设模型总体 accuracy=85%，但通过 classification_report 可能发现：
-   "cat" 的 Recall 仅 60% → 模型频繁把猫误判为狗
-   "truck" 的 Precision 高达 98% → 模型对卡车非常保守，几乎不误报
-   macro F1 = 0.82 vs weighted F1 = 0.85 → 说明少数/难分类别拖累了整体

> 🔍 **实践建议**: 拿到报告后，优先关注 **F1-Score 最低的 2-3 个类别**，这些就是模型的短板。可进一步结合混淆矩阵（`ConfusionMatrixDisplay`）查看具体被误判成了哪些类，从而针对性地进行数据增强或损失函数调整（如 class-weighted loss）。

下面为你逐项拆解报告中的核心指标：

### 1. 三大核心指标（针对每个类别）

| 指标 | 中文名称 | 含义与关注点 |
| :--- | :--- | :--- |
| **Precision** | 精确率 / 查准率 | **“预测为正的样本中，有多少是真的正？”**衡量模型预测的*准确性*。如果该值低，说明模型容易“误报”（把别的类错认成该类）。 |
| **Recall** | 召回率 / 查全率 | **“所有真实的正样本中，有多少被找出来了？”**衡量模型预测的*完整性*。如果该值低，说明模型容易“漏报”（把该类的图片错认成别类）。 |
| **F1-Score** | F1 分数 | Precision 和 Recall 的调和平均数：$2 \times \frac{P \times R}{P + R}$综合评价指标。当 P 和 R 不平衡时，F1 比单纯的平均值更能反映真实水平。 |
| **Support** | 样本数 | 测试集中该类别的真实样本数量。这里每类都是 1000，说明数据集是绝对平衡的。 |

### 3. 全局汇总指标解释

由于你的测试集是完全平衡的（每类 Support 相同），你会发现 **Accuracy = Macro Avg = Weighted Avg**，三者完全相等（均为 0.9354/0.9355）。但在不平衡数据集中，它们的区别至关重要：

| 汇总指标 | 计算方式 | 适用场景 |
| :--- | :--- | :--- |
| **Accuracy** | 全局预测正确的总数 / 总样本数 | 仅适用于类别平衡的数据集。在不平衡时会掩盖少数类的糟糕表现。 |
| **Macro Avg** | 各类别指标的**简单算术平均** | **平等对待每一个类别**。无论样本多少，每个类的权重一样。适合评估模型对“所有类别”的整体学习能力。 |
| **Weighted Avg** | 按各类别 Support **加权平均** | **考虑了类别不平衡**。样本多的类别对最终得分影响更大。适合评估模型在实际业务分布下的真实表现。 |

### 💡 下一步优化建议

基于这份报告，你可以采取以下针对性措施：

1.  **聚焦困难类别**：单独提取 `cat` 和 `dog` 的错误分类样本（可通过混淆矩阵定位），人工查看这些图片是否确实模糊难辨，或是存在标注噪声。

3.  **调整损失函数**：如果希望进一步提升弱势类别的表现，可以尝试使用 Label Smoothing 或 Focal Loss，降低易分类样本（如汽车、青蛙）的权重，迫使模型将梯度更新集中在猫和狗上。
